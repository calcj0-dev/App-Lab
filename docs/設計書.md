## 1. 構成と技術

```
[スマホのブラウザ（X・note のアプリの中など）]
   │ 1ページの HTML（アプリの一覧は HTML に書き込み済み）
   ▼
[Vercel（静的サイト）]  … app-lab-rust.vercel.app（U16）
   │
   ├─ 各アプリへのリンク（UTM 付き。同じタブで開く）
   └─ X・note へのリンク
計測：Vercel Analytics（ページの表示・参照元）
```

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 作り方 | **ビルドのときに JSON から HTML を作る**（静的サイト） | 検索エンジンがアプリの一覧を読める。開いたときに計算がいらないので速い |
| 道具 | Vite＋TypeScript＋Vitest（前作と同じ） | 前作の土台・検査の仕組みを流用できる |
| 画面の部品 | フレームワークなし。HTML＋CSS | 1ページで動きが少ないので、要らない |
| ページで動く JavaScript | **Vercel Analytics だけ** | 速さのため |
| 置き場所 | Vercel（無料プラン） | 決定済み（P1） |

- HTML を作る処理は `src/render/` の関数（データ → HTML の文字列）にまとめ、Vite のプラグイン（`transformIndexHtml`）から呼ぶ。関数なのでテストしやすい
- サーバー・データベース・ログインはない

## 4. データの形（JSON）
`data\` の4つのファイル。実装では `src/data/` にそのまま置く。

| ファイル | 中身 | 直す頻度 |
| --- | --- | --- |
| `apps.json` | **アプリの一覧**（文章も含む。アプリを足すときはこのファイルだけ直す） | アプリを足す・状態を変えるとき |
| `news.json` | お知らせ | 公開・大きな更新のとき |
| `site.json` | 作者の情報、分類の並び、UTM、OGP 画像、色 | ほぼ直さない |
| `i18n/ja.json` | 画面の決まった文言（見出し・ボタン・サイトの説明など） | ほぼ直さない |

- 言語に関わる文章は `{ "ja": "…" }` の形で持つ。英語を足すときは `"en"` を足す（10.2）
- `apps.json`・`news.json`・`site.json` の一番上の `"version"` は**データの形の版**（今は `1`）。項目の名前や型を変えたときだけ上げる。アプリを足す・文章を直すだけなら変えない。検査は、プログラムが知っている版と一致しなければ止める（9.1）
- `apps.json` の文章を `i18n/` に分けないのは、**アプリを足すときに直すファイルを1つにするため**（要件定義書 P5）

### 4.1 `apps.json` の項目
| 項目 | 型 | 必須 | 意味 | 例 |
| --- | --- | --- | --- | --- |
| `id` | 文字列 | ◯ | アプリの識別子。英小文字・数字・ハイフン。**一度決めたら変えない**（UTM と、後で作る紹介ページのURLに使う） | `"tameru"` |
| `category` | 文字列 | ◯ | 分類。`site.json` の `categories` のどれか | `"tool"`／`"game"` |
| `featured` | 真偽 | ◯ | 大きいカードにするか。**全体でちょうど1つ**（TAMERU） | `true` |
| `status` | 文字列 | ◯ | `"public"`（公開中）／`"coming"`（準備中） | `"public"` |
| `order` | 数 | ◯ | 分類の中での並び順（小さいほど上）。同じ分類で重ならない | `1` |
| `url` | 文字列／null | ◯ | アプリのURL（`https://`）。準備中は `null` | `"https://tameru-lovat.vercel.app"` |
| `image` | 文字列／null | ◯ | `public/` からの画像の場所。ないとき・**画像ファイルをまだ置いていないとき**は `null`（仮の画像になる）。ファイルを置いてから書く（6.2） | `"images/tameru.webp"` |
| `name` | 言語ごとの文字列 | ◯ | 名前 | `{ "ja": "TAMERU（タメル）" }` |
| `shortName` | 言語ごとの文字列 | — | 短い名前（12字以内）。大きいカードのボタン「{name} を使ってみる」に入る。なければ `name` を使う | `{ "ja": "TAMERU" }` |
| `tagline` | 言語ごとの文字列 | ◯ | 一言（30字以内） | `{ "ja": "貯めて、眺めて、続けられる資産管理" }` |
| `description` | 言語ごとの文字列 | ◯ | 説明（90字以内） | 下の例 |
| `tags` | 言語ごとの文字列の一覧 | ◯ | タグ（3つまで、各8字以内） | `{ "ja": ["無料", "口座連携なし", "PC・スマホ"] }` |
| `notice` | 言語ごとの文字列／null | ◯ | 注意書き（50字以内）。いらなければ `null` | `{ "ja": "ゲームであり、投資助言ではありません。相場は架空です。" }` |
| `notes` | 一覧 | ◯ | 関連する note 記事。`{ "title": { "ja": "…" }, "url": "https://note.com/teddd19/n/…" }`。なければ `[]`。カードには先頭の1本だけ出す | `[]` |
| `imageAlt` | 言語ごとの文字列 | ◯ | 画像の説明（読み上げ・検索用） | `{ "ja": "TAMERU の画面" }` |

## 7. 計測と UTM

### 7.1 UTM（P10）
各アプリへのリンクを、ビルドのときに次の形にする（`src/render/utm.ts`）。
```
<アプリのURL> に次を足す
utm_source=portal
utm_medium=referral
utm_campaign=ted_app_lab
utm_content=<押した場所>   … featured（TAMERU の大きいカード）／card（ふつうのカード）
```
例：`https://tameru-lovat.vercel.app/?utm_source=portal&utm_medium=referral&utm_campaign=ted_app_lab&utm_content=featured`

- URL の部品を組み立てる仕組み（`URL` と `searchParams`）で足す。アプリのURLにもともと `?lang=en` などがあっても壊れない
- X・note のリンクには付けない

### 7.2 クリック数の数え方（U9：Vercel Analytics だけ）
- まとめサイトには **Vercel Analytics** を入れる（`@vercel/analytics` の `inject()`）。分かるのは、表示数と、どこから来たか（X・note など）
- **各アプリへ移った数は、各アプリの Vercel Analytics の「Referrers（参照元）」で、`app-lab-rust.vercel.app` の数を見る**
  - 公開中の4つ（TAMERU・積立投資を超えろ！・シティチェイス・永田町ポリティクス）には Vercel Analytics が入っている（2026-11-11 にリポジトリで確認）
  - 準備中のアプリは、公開するときに Vercel Analytics を入れる
- 無料プランでは、クリックの記録・UTM の集計は見られない。データは1か月分だけ残る
- Vercel Analytics の無料枠（月5万件）は、**すべてのアプリと合算**。まとめサイトの分も足される

### 7.3 記録の残し方（月に1回）
マーケティングの記録（`marketing\apps\…\log.md` など、マネージャーが決めた場所）に、次の表を残す。
| 月 | まとめサイトの表示数 | 主な来た場所（X・note…） | TAMERU へ | 積立投資を超えろ！へ | シティチェイスへ | 永田町ポリティクスへ | … |
| --- | --- | --- | --- | --- | --- | --- | --- |

- 数は、各アプリの Vercel Analytics の Referrers で、期間を「過去30日」にしたときの `app-lab-rust.vercel.app` の数

## 9. データの検査とテスト

### 9.1 データの検査（ビルドの前に自動で動く。`scripts/validate-data.ts`）
間違いがあれば**ビルドを止めて**、どのアプリのどの項目が悪いかを日本語で出す。Vercel でも同じ検査が動くので、間違ったデータは公開されない。

| 検査 | 内容 |
| --- | --- |
| 必須 | 4.1 の必須項目がある。型が合っている |
| `id` | 英小文字・数字・ハイフンだけ。重ならない |
| `category` | `site.json` の `categories` にある |
| `featured` | 全体でちょうど1つ |
| `status` と `url` | `public` なら `https://` で始まる URL がある。`coming` なら `null` |
| `order` | 同じ分類の中で重ならない |
| `image` | `null` か、`public/` にファイルがある。80KB以下 |
| `author.avatar` | `null` か、`public/` にファイルがある。80KB以下 |
| `version` | 3つのデータファイルの `version` が、プログラムが知っている版（今は `1`）と同じ |
| 文字数 | `tagline` 30字以内、`description` 90字以内、`shortName` 12字以内、`tags` 3つまで・各8字以内、`notice` 50字以内、お知らせ 40字以内 |
| 言語 | 文章の項目に `ja` がある |
| `notes` | URL が `https://note.com/` で始まる |
| `news` | 日付が `YYYY-MM-DD`、`appId` が `null` か `apps.json` にある |
| 文言 | `i18n/ja.json` に必要なキーがそろっている |

## 11. アプリを足す・直す手順
Ted が自分でできるように書く。

### 11.1 新しいアプリを足す
1. `data/apps.json` の `apps` の中に、ほかのアプリを1つコピーして貼り、中身を書き換える（4.1 の表を見ながら）
   - `id` は英小文字とハイフンで、ほかと重ならない名前（例 `takarakuji-gacha`）
   - 公開前なら `"status": "coming"`、`"url": null`

3. 公開したことを知らせたいときは `data/news.json` の `items` の先頭に1行足す
4. `npm run check`（データの検査とテスト）で問題がないことを確かめる
5. GitHub に push すると、Vercel が自動で公開する

### 11.2 準備中のアプリを公開に変える
1. `apps.json` のそのアプリの `status` を `"public"`、`url` をアプリのURLにする
2. アプリの OGP 画像ができていれば、11.1 の 2 で画像を差し替える
3. `news.json` に「〇〇を公開しました」を足す
4. `npm run check` → push

### 11.3 note の記事を足す
- `apps.json` のそのアプリの `notes` に `{ "title": { "ja": "記事の題名" }, "url": "https://note.com/teddd19/n/…" }` を足す（先頭の1本がカードに出る）
